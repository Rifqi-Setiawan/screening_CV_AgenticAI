Target System: AI CV Screening & Candidate Ranking (CV_Extractor & Screening Engine)
Objective: Meningkatkan Akurasi Ekstraksi Entitas dari 74.5% menjadi >98.5% pada 
           Dokumen Dunia Nyata yang Kotor, Multi-Kolom (Canva), dan Bundled.

1. EXECUTIVE ARCHITECTURE OVERVIEW
--------------------------------------------------------------------------------
Masalah utama pada pipeline ekstraksi generasi pertama (berbasis ekstraksi teks 
heuristik PyMuPDF/pdfplumber + Tesseract OCR + single-pass regex/LLM) adalah 
hilangnya "kesadaran spasial dan semantik dokumen" (spatial & document-level 
semantic awareness). Ketika PDF diratakan menjadi string mentah (flat text), 
informasi seperti ukuran font, koordinat kolom, batas antar halaman, dan konteks 
visual hilang sepenuhnya.

Untuk mencapai akurasi >98.5% di produksi dengan efisiensi biaya dan latensi 
yang terkendali, kita menerapkan arsitektur "Multi-Tier Cascading & Agentic 
Verification Pipeline":

A. Topologi Sistem (4-Stage Pipeline):
   [Stage 0: Ingestion & Cross-Signal Harvester]
     -> Ekstraksi metadata file, sanitasi nama file, ekstraksi hyperlink PDF 
        tersembunyi (URI annotations), dan analisis kepadatan teks per halaman.
   
   [Stage 1: Page-Level Classifier & Boundary Isolation Gate]
     -> Memindai dokumen multi-halaman (1 hingga 20+ halaman) dan mengklasifikasi 
        setiap halaman ke dalam taksonomi: {CV_CORE, COVER_LETTER, PORTFOLIO, 
        CERTIFICATE, TRANSCRIPT_IJAZAH, NOISE_ID}. Hanya halaman CV_CORE yang 
        masuk ke pipeline ekstraksi riwayat kerja utama.
   
   [Stage 2: Adaptive Layout-Aware & Multimodal Routing (Tiered Extraction)]
     -> Tier 1 (Fast Layout-Aware Digital Route - ~65% trafik, <1.5 detik):
        Menggunakan Docling (IBM) atau Surya Layout + PyMuPDF blok spasial untuk 
        merekonstruksi urutan baca (reading order) kolom ganda secara deterministik 
        menjadi Markdown terstruktur.
     -> Tier 2 (Multimodal Vision Route - ~35% trafik, 2.5 - 4.5 detik):
        Dipicu otomatis jika: (a) kepadatan karakter < 50 char/halaman (scan), 
        (b) terdeteksi font encoding rusak (cid:xxx / mojibake), (c) terdeteksi 
        layout grafis berat (Canva kompleks/skill bar visual), atau (d) Tier 1 
        menghasilkan confidence score rendah. Halaman CV_CORE dirender menjadi 
        citra 150-200 DPI dan dikirim langsung ke Vision-Language Model (VLM) 
        seperti Gemini 2.5 Flash / Qwen2.5-VL-72B.

   [Stage 3: Anti-Bias Entity Resolution & Self-Correcting Verification Loop]
     -> Mesin deterministik + LLM Judge ringan yang memvalidasi silang kandidat 
        nama dari hasil ekstraksi dengan 5 sinyal ortogonal (Email local-part, 
        LinkedIn slug, Filename, Header/Footer signature, dan Kamus Negatif 
        Jabatan/Institusi).

2. DOCUMENT BOUNDARY ISOLATION & SEGMENTATION
--------------------------------------------------------------------------------
Kasus bundel dokumen 10-19 halaman (CV + Portofolio + Ijazah + Transkrip + 
Sertifikat + KTP) adalah penyebab utama tercemarnya riwayat kerja (proyek di 
halaman 15 dianggap pengalaman kerja) dan kegagalan ekstraksi nama (halaman 1 
berupa Cover Page "TENTANG SAYA" atau "PORTOFOLIO").

A. Taksonomi Klasifikasi Halaman (Page-Level Taxonomy):
   Setiap halaman $p_i \in \{1 \dots N\}$ diklasifikasikan ke dalam salah satu kelas:
   1. COVER_PAGE_OR_INTRO : Halaman judul portofolio ("Curriculum Vitae & Portfolio", 
                            "Tentang Saya" esai penuh).
   2. CV_CORE             : Halaman inti resume (memuat kontak, ringkasan, pengalaman 
                            kerja, pendidikan, skill). Umumnya 1-3 halaman.
   3. COVER_LETTER        : Surat lamaran kerja ("Hal: Lamaran Pekerjaan", "Kepada Yth.").
   4. PORTFOLIO_SHOWCASE  : Halaman daftar proyek visual, tangkapan layar aplikasi/desain, 
                            studi kasus kampanye digital marketing, gambar teknik sipil.
   5. ACADEMIC_CREDENTIAL : Ijazah, Transkrip Nilai (tabel mata kuliah & SKS), SKL.
   6. CERTIFICATE_ID      : Sertifikat kursus/webinar, KTP, NPWP, BPJS, SKCK.

B. Algoritma Fast Page-Boundary Classifier (<50ms untuk 20 halaman):
   Sebelum mengirim dokumen ke parser berat atau VLM, jalankan "Lightweight Page 
   Fingerprinting" per halaman menggunakan fitur hibrida (Teks + Geometri Visual):

   1. Fitur Heuristik & Densitas Spasial per Halaman:
      - Text Token Count ($T_c$): Jumlah kata pada halaman. Sertifikat & Portofolio 
        visual cenderung memiliki $T_c < 80$ dengan rasio area gambar $> 60\%$.
      - Image-to-Page Area Ratio ($R_{img}$): Dihitung dari bounding box XObject 
        image di PyMuPDF. Jika 1 gambar mencakup $>85\%$ halaman -> indikasi kuat 
        scan Ijazah/Sertifikat/KTP.
      - Aspect Ratio & Orientation: Halaman landscape di tengah dokumen portrait 
        hampir pasti merupakan Sertifikat atau Portofolio presentasi.

   2. Lexical Marker Scoring (Skor Berbobot per Halaman):
      - Skor `CV_CORE` (+): Kehadiran penanda seksi ("Pengalaman Kerja", "Work Experience", 
        "Riwayat Pendidikan", "Education", "Skills", "Keahlian") + pola rentang tanggal 
        berulang ($\ge 2$ pola bulan-tahun) + entitas kontak (email/telepon).
      - Skor `COVER_LETTER` (+): Frasa "Kepada Yth", "Dengan hormat", "Sehubungan dengan 
        informasi lowongan", "Hormat saya", paragraf panjang dengan tanda tangan di bawah.
      - Skor `ACADEMIC_CREDENTIAL` (+): Kata kunci "Transkrip Akademik", "Ijazah", 
        "Indeks Prestasi Kumulatif", "SKS", "Rektor", "Dekan", "Nomor Induk Mahasiswa", 
        "Kementerian Pendidikan".
      - Skor `CERTIFICATE_ID` (+): Kata kunci "Certificate of Completion", "Diberikan kepada", 
        "Has successfully completed", "NIK", "Provinsi", "Kartu Tanda Penduduk".
      - Skor `PORTFOLIO_SHOWCASE` (+): Kata kunci berulang "Project Overview", "Tech Stack", 
        "Role:", "Link Demo", " Screenshot", "Hasil Desain", atau halaman dengan $>3$ 
        gambar medium dan teks deskriptif pendek.

   3. Aturan Transisi Sekuensial (Hidden Markov / State Machine Rules):
      - Jika Halaman 1 adalah `COVER_LETTER`, maka pencarian `CV_CORE` digeser mulai 
        Halaman 2.
      - Begitu `CV_CORE` ditemukan (misal Halaman 1-2) dan Halaman 3-4 beralih ke 
        `PORTFOLIO_SHOWCASE` atau `ACADEMIC_CREDENTIAL`, sistem mengaktifkan "Hard 
        Boundary Cut": halaman setelah `CV_CORE` DILARANG masuk ke prompt ekstraksi 
        `work_experience` utama.
      - Ekstraksi Sekunder (Opsional): Halaman `PORTFOLIO_SHOWCASE` diekstrak secara 
        terpisah ke dalam array `portfolio_projects[]` (bukan `work_experience[]`), 
        sehingga proyek lepas atau tugas kuliah di halaman 15 tidak menggelembungkan 
        kalkulasi "Total Years of Experience" (YoE).

3. VISUAL & MULTIMODAL EXTRACTION PIPELINE
--------------------------------------------------------------------------------
Mengatasi dokumen multi-kolom Canva, urutan baca (reading order) yang hancur, 
skill bar grafis, dan font encoding rusak.

A. Deteksi Kerusakan Font Encoding (Mojibake / Custom Subset Fonts):
   Banyak PDF ekspor Canva atau desain kustom tidak menyematkan tabel `ToUnicode` 
   yang valid, menghasilkan karakter `\ufffd`, `(cid:12)`, atau simbol acak.
   - Metrik Deteksi: Hitung `Printable ASCII + Common Latin/Indonesian Ratio` dan 
     `Dictionary Word Hit Ratio` (persentase token yang cocok dengan kamus kata 
     umum Bahasa Indonesia + Inggris + istilah teknis IT/Bisnis/Sipil).
   - Trigger: Jika `CID_Count > 5` ATAU `Valid_Word_Ratio < 0.45` ATAU `Total_Chars < 60` 
     pada halaman `CV_CORE`, batalkan ekstraksi teks PDF dan paksa rute **Tier 2 
     (Direct Vision/VLM Extraction)** pada citra hasil render PDF.

B. Rekonstruksi Multi-Kolom Deterministik (Tier 1: XY-Cut + Spatial Clustering):
   Jika dokumen digital valid (bukan scan/mojibake), jangan pernah gunakan 
   `page.get_text("text")` biasa karena PyMuPDF membaca berdasarkan urutan stream 
   objek PDF, sering kali mencampur teks kolom kiri dan kanan pada baris horizontal 
   yang sama.
   
   Gunakan algoritma **Recursive XY-Cut dengan Projection Profile** atau integrasikan 
   **IBM Docling / Surya Layout**:
   1. Ekstrak semua blok teks beserta koordinat bounding box: $(x_0, y_0, x_1, y_1)$, 
      nama font, ukuran font ($s$), dan warna.
   2. Deteksi "Header Banner" (Full-Width Top Region): Cari blok di $y_0 < 0.22 \times H_{page}$ 
      yang melintasi garis tengah halaman atau berada di area atas sebelum pemisahan 
      kolom dimulai.
   3. Proyeksi Histogram Vertikal: Cari "lembah kosong" (whitespace gutter vertikal) 
      antara $x = 0.25 \times W_{page}$ hingga $x = 0.65 \times W_{page}$.
      - Jika ditemukan gutter vertikal yang konsisten sepanjang $>50\%$ tinggi halaman:
        Pisahkan blok menjadi `Left_Column` (biasanya sidebar: Kontak, Skill, Bahasa, 
        Edukasi pendek) dan `Right_Column` (biasanya konten utama: Tentang Saya, 
        Pengalaman Kerja, Pendidikan detail).
   4. Urutkan masing-masing zona secara independen dari atas ke bawah ($y_0$ ascending), 
      lalu gabungkan secara sekuensial dengan tag penanda eksplisit untuk LLM:
      ```markdown
      [DOCUMENT_HEADER_ZONE]
      ...
      [LEFT_SIDEBAR_COLUMN]
      ...
      [MAIN_CONTENT_COLUMN]
      ...
      ```

C. Multimodal VLM Pipeline untuk Canva Kompleks & Elemen Visual (Tier 2):
   Pada CV modern (terutama Digital Marketing, UI/UX, dan Fresh Graduate pengguna 
   template Canva):
   - Skill sering direpresentasikan dengan **Progress Bar (80%), Bintang (4/5), 
     atau Lingkaran Persentase** tanpa teks level keahlian.
   - Ikon telepon, email, LinkedIn, dan lokasi menggantikan label teks ("Email:", "HP:").
   - Cara Kerja Tier 2:
     1. Render halaman `CV_CORE` (maksimal 3 halaman) menggunakan `pypdfium2` atau 
        `fitz` (PyMuPDF) pada resolusi **150-200 DPI** (lebar ~1240px hingga 1650px, 
        format WebP kualitas 85 untuk efisiensi ukuran payload).
     2. Kirim citra halaman bersama dengan metadata hasil ekstraksi Stage 0 (URI 
        tersembunyi dan nama file) langsung ke VLM (Gemini 2.5 Flash atau Qwen2.5-VL).
     3. Instruksikan VLM dalam System Prompt untuk:
        - Membaca kolom kiri dan kolom kanan sebagai blok terpisah.
        - Mengonversi grafik visual (progress bar / bintang pada seksi Skills) menjadi 
          estimasi numerik atau kategori (`Beginner`, `Intermediate`, `Advanced`, 
          `Expert`) berdasarkan proporsi panjang bar visual.
        - Mengasosiasikan teks di sebelah ikon amplop sebagai email, ikon gedung/pin 
          sebagai domisili, dan ikon rantai/LinkedIn sebagai URL profil.

4. ENTITY RESOLUTION & ANTI-BIAS VERIFICATION ENGINE
--------------------------------------------------------------------------------
Ini adalah inti perbaikan untuk mendongkrak akurasi ekstraksi Nama dari 74.5% 
ke >98.5% dan memberantas *Headline Bias*, *Institutional Header Bias*, 
*Merged Portfolio Section Header*, serta *Narrative Opening*.

A. Mengapa Parser Lama Gagal (Root Cause Analysis):
   Parser lama mengandalkan asumsi naif: *"Teks dengan font terbesar atau baris 
   pertama di bagian atas halaman 1 adalah Nama Pelamar."*
   Di dunia nyata:
   - Pelamar menulis **FULLSTACK DEVELOPER** (font 28pt) di atas namanya (font 14pt).
   - Template kampus atau kop surat menempatkan **STMIK DIPANEGARA** atau **UNIVERSITAS 
     MUHAMMADIYAH** di baris paling atas.
   - Bundel dokumen diawali judul seksi **TENTANG SAYA** atau **CURRICULUM VITAE**.
   - Pelamar langsung menulis paragraf: *"Fresh graduate jurusan Teknik Sipil yang 
     memiliki semangat belajar tinggi..."* tanpa header nama yang mencolok.

B. Arsitektur "5-Signal Cross-Verification & Anti-Bias Filter":
   Sistem TIDAK BOLEH menetapkan `candidate_name` hanya dari satu baris teks secara 
   buta. Sistem harus mengumpulkan **Kandidat Nama ($C_1, C_2, \dots, C_k$)** dan 
   menilainya terhadap 5 sinyal independen + 4 filter negatif:

   1. Empat Filter Penolakan Keras (Hard Negative Lexicon & Pattern Filters):
      Setiap kandidat string nama $S$ otomatis DIDISKUALIFIKASI atau diberi penalti 
      skor $-100$ jika memenuhi salah satu kondisi berikut:
      
      a) Job Title / Headline Blocklist (Mengatasi Pola 1 - Headline Bias):
         Regex & leksikon pencocokan terhadap ratusan istilah jabatan dan bidang:
         `(?i)\b(developer|engineer|programmer|analyst|marketing|specialist|manager|director|officer|admin|administrator|staff|staf|supervisor|coordinator|koordinator|consultant|konsultan|designer|desainer|architect|arsitek|accountant|akuntan|auditor|recruiter|hrd|human resources|sales|copywriter|content creator|social media|seo|sem|ui/ux|frontend|front-end|backend|back-end|fullstack|full-stack|devops|data scientist|civil|sipil|drafter|estimator|pelaksana|pengawas|fresh graduate|lulusan baru|intern|magang)\b`
         *Catatan Penting:* Jika baris pertama adalah `"Rifqi Setiawan - Backend Developer"`, 
         sistem melakukan *Delimiter Stripping* pada pemisah (`-`, `|`, `/`, `,`) 
         dan membuang segmen yang mengandung token jabatan, menyisakan `"Rifqi Setiawan"`.

      b) Institutional & Academic Blocklist (Mengatasi Pola 2 - Institutional Header):
         Diskualifikasi string yang mengandung entitas institusi:
         `(?i)\b(universitas|institut|sekolah tinggi|politeknik|akademi|stmik|stie|stkip|stis|sma|smk|ma|yayasan|fakultas|jurusan|program studi|prodi|departemen|kementerian|dinas|pt\.?|cv\.?|tbk|persero|university|institute|college|school|faculty|department)\b`

      c) Document Meta & Section Header Blocklist (Mengatasi Pola 3 - Portfolio Header):
         Diskualifikasi judul seksi:
         `(?i)^\s*(curriculum vitae|resume|biodata|data pribadi|personal data|tentang saya|about me|profil|profile|ringkasan|summary|portofolio|portfolio|daftar riwayat hidup|lamaran pekerjaan|cover letter)\s*$`

      d) Narrative Sentence Filter (Mengatasi Pola 4 - Narrative Opening):
         Nama manusia di Indonesia/internasional hampir selalu terdiri dari 1 hingga 6 
         kata benda nama diri (Proper Nouns), tanpa kata kerja atau konjungsi naratif.
         Diskualifikasi kandidat nama jika:
         - Jumlah kata $> 6$ kata.
         - Mengandung kata hubung/kerja/sifat naratif: `(?i)\b(adalah|merupakan|memiliki|yang|dengan|sebagai|lulusan|berpengalaman|mampu|bekerja|tinggi|semangat|belajar|saya|seorang|profesional|berdedikasi|lahir|tahun)\b`.
         *Self-Correction Rule untuk Pola 4:* Jika di dalam paragraf naratif terdapat 
         pola perkenalan eksplisit seperti `"Nama saya [X]"` atau `"Saya [X], lulusan..."`, 
         ekstrak grup `[X]` dan validasi dengan sinyal email/filename.

   2. Lima Sinyal Validasi Silang Positif (Orthogonal Positive Anchors):
      Sebelum dan sesudah LLM mengekstrak nama dari tampilan visual/teks CV, sistem 
      mengekstrak 4 jangkar identitas deterministik dari dokumen:

      - **Anchor A (Email Local-Part):**
        Contoh: `muhammad.fajar99@gmail.com` -> tokenisasi alfabetik -> `["muhammad", "fajar"]`.
      - **Anchor B (LinkedIn URL Slug / PDF URI Annotation):**
        Contoh: `linkedin.com/in/fajar-pratama-2819a` -> `["fajar", "pratama"]`.
      - **Anchor C (Cleaned Document Filename):**
        Contoh: `CV_Muhammad_Fajar_Pratama_CivilEng_2026.pdf` -> hapus stopword 
        (`cv`, `resume`, `lamaran`, `portofolio`, nama jabatan, angka tahun) -> 
        `["muhammad", "fajar", "pratama"]`.
      - **Anchor D (Explicit Key-Value Biodata Row):**
        Pada banyak CV Indonesia (terutama format tabel atau surat lamaran), nama 
        muncul secara eksplisit setelah label `"Nama Lengkap : Muhammad Fajar Pratama"` 
        atau di bagian tanda tangan bawah `"Hormat saya, (Muhammad Fajar Pratama)"`.
      - **Anchor E (Visual Header / Typography Candidate):**
        Kandidat nama yang diekstrak oleh VLM/LLM dari bagian atas halaman CV_CORE 
        setelah melewati 4 Filter Penolakan Keras di atas.

   3. Algoritma Konsensus Skor Identitas (Identity Consensus Scoring):
      Untuk setiap kandidat nama $C_i$ yang lolos filter negatif, hitung skor 
      kemiripan token (Jaro-Winkler / Token Set Ratio via `rapidfuzz`) terhadap 
      Anchor A, B, C, dan D:
      $$Score(C_i) = 0.35 \cdot S_{visual}(C_i) + 0.25 \cdot \text{Sim}(C_i, \text{Email}) + 0.20 \cdot \text{Sim}(C_i, \text{LinkedIn}) + 0.10 \cdot \text{Sim}(C_i, \text{Filename}) + 0.10 \cdot \text{Sim}(C_i, \text{BiodataKey})$$
      
      - **Kasus Pemulihan Ekstrem (Zero-Header Name Recovery):**
        Bagaimana jika pelamar menggunakan "Narrative Opening" (Pola 4) dan *sama sekali 
        lupa* menulis namanya di header halaman 1?
        Sistem akan mendeteksi bahwa kandidat visual $C_{visual}$ ditolak oleh 
        *Narrative Sentence Filter*. Sistem kemudian mencari irisan konsensus antara 
        `Anchor A (Email)`, `Anchor B (LinkedIn)`, `Anchor C (Filename)`, dan `Anchor D 
        (Halaman Cover Letter / Tanda Tangan / Sertifikat Lampiran)`. Jika 2 dari 4 
        anchor tersebut memiliki kesamaan $\ge 0.85$ (misal Filename `"CV_Rina_Wijaya.pdf"` 
        dan Email `"rinawijaya22@gmail.com"`), nama `"Rina Wijaya"` berhasil dipulihkan 
        dengan akurasi 100%!

5. WORK EXPERIENCE & EDUCATION PARSER
--------------------------------------------------------------------------------
Mengatasi format tanggal yang kacau, pencampuran pengalaman organisasi/proyek 
dengan pekerjaan purnawaktu, dan ekstraksi skill kontekstual.

A. Pemisahan Tegas Kategori Pengalaman (Strict Experience Categorization):
   Di dalam skema ekstraksi, paksa model/parser untuk membedakan 4 entitas 
   berikut ke dalam array JSON yang terpisah:
   1. `work_experience[]` : Hanya pekerjaan profesional (Full-time, Contract, 
                            Part-time, Freelance komersial, dan Internship/Magang 
                            resmi di perusahaan/instansi).
   2. `organizational_experience[]` : BEM, Himpunan Mahasiswa (HIMA), kepanitiaan 
                                      kampus, organisasi sosial/relawan.
   3. `projects_and_portfolio[]` : Tugas akhir/skripsi, proyek bootcamp, proyek 
                                   pribadi, studi kasus portofolio.
   4. `education[]` : Pendidikan formal (SMA/SMK, D3, D4/S1, S2) dipisahkan dari 
                      `certifications_and_courses[]` (Bootcamp, webinar, kursus singkat).

   *Aturan Anti-Polusi Durasi Kerja:* Saat menghitung `total_experience_months` untuk 
   kebutuhan ranking kandidat, buat dua metrik terpisah:
   - `professional_fulltime_months` (Hanya Full-time, Contract, Part-time).
   - `internship_and_freelance_months` (Magang / Freelance).
   Pengalaman organisasi dan proyek kuliah memiliki bobot `0 bulan` pada kalkulasi 
   masa kerja profesional.

B. Normalisasi Tanggal Multi-Format Bahasa Indonesia & Internasional:
   Format tanggal pada CV Indonesia sangat bervariasi: `"Jan 2022 - Agu 2024"`, 
   `"Mei '21 - Sekarang"`, `"2020/03 - 2021/11"`, `"02-2023 s/d Saat ini"`, 
   `"Oktober 2022 - Present"`, `"2019 - 2021"`, bahkan tanpa spasi `"Jul2022-Des2023"`.

   Pipeline Normalisasi Deterministik (Post-Processing Python):
   1. Kamus Pemetaan Bulan Dwibahasa Lengkap:
      - `01`: `jan, januari, january`
      - `02`: `feb, peb, februari, pebruari, february`
      - `03`: `mar, maret, march`
      - `04`: `apr, april`
      - `05`: `mei, may`
      - `06`: `jun, juni, june`
      - `07`: `jul, juli, july`
      - `08`: `agu, ags, agust, agustus, aug, august`
      - `09`: `sep, sept, september`
      - `10`: `okt, october, oktober, oct`
      - `11`: `nov, nop, november, nopember`
      - `12`: `des, dec, desember, december`
   2. Deteksi Token `IS_CURRENT`:
      `(?i)\b(sekarang|saat ini|kini|present|current|now|ongoing|masih bekerja|aktif|hingga kini|sampai sekarang)\b`
      Jika terdeteksi, set `end_date = CURRENT_YEAR_MONTH` (misal `"2026-10"`) dan 
      flag `is_current = True`.
   3. Penanganan Tanggal Hanya Tahun (`"2021 - 2023"`):
      - Jika `start_year == end_year` (misal `"2022 - 2022"`): asumsikan durasi 
        konservatif 6 bulan (atau 3 bulan jika bertipe `Internship`).
      - Jika berbeda tahun tanpa bulan: set `start_month = 06` (pertengahan tahun) 
        atau gunakan batas konservatif agar tidak menggelembungkan durasi secara 
        tidak adil, dan beri flag `date_granularity = "YEAR_ONLY"`.

C. Algoritma Interval-Merging untuk Kalkulasi Durasi Kerja (Anti-Double Counting):
   Pelamar sering memiliki dua pekerjaan paruh waktu atau magang yang tumpang tindih 
   (overlap) di periode yang sama (misal: Kerja A dari Jan 2023 - Des 2023, dan 
   Freelance B dari Jun 2023 -Sep 2023). Menjumlahkan durasi secara naif akan 
   menghasilkan $12 + 4 = 16$ bulan di dalam rentang 1 tahun kalender.
   
   Solusi: Gunakan **Calendar Interval Union Algorithm**:
   - Konversi setiap riwayat kerja menjadi interval indeks bulan $[M_{start}, M_{end}]$ 
     di mana $M = \text{Year} \times 12 + \text{Month}$.
   - Urutkan semua interval berdasarkan $M_{start}$ ascending.
   - Gabungkan interval yang tumpang tindih ($M_{start, i+1} \le M_{end, i}$) menjadi 
     satu interval kontinu $[\min(M_{start}), \max(M_{end})]$.
   - Jumlahkan panjang interval hasil gabungan untuk mendapatkan `net_experience_months` 
     yang bebas duplikasi waktu.

D. Contextual Tech Stack & Competency Extraction:
   Jangan hanya mengambil skill dari bagian "Skills" (karena pelamar sering 
   mencantumkan skill yang hanya pernah mereka dengar).
   - Ekstrak `demonstrated_skills[]` langsung dari setiap item `work_experience` 
     dan `projects` (contoh: jika di deskripsi pengalaman kerja tertulis *"Membangun 
     REST API menggunakan FastAPI, PostgreSQL, dan Redis"*, maka `FastAPI`, 
     `PostgreSQL`, dan `Redis` ditandai sebagai **Verified Experience Skill** dengan 
     bobot lebih tinggi pada fase Ranking dibandingkan skill yang hanya tertulis 
     di sidebar).

A. Empat Filter Penolakan Keras (Hard Negative Lexicons)

Setiap kandidat nama 
𝐶
C yang diusulkan oleh parser atau VLM harus melewati 4 saringan deterministik berikut:

Pola 1 Guardrail — Job Title & Role Headline Blocklist:

Jika string kandidat mengandung kata jabatan: developer, engineer, programmer, analyst, marketing, specialist, manager, officer, admin, staff, staf, supervisor, designer, desainer, architect, arsitek, accountant, akuntan, drafter, estimator, pelaksana, pengawas, frontend, backend, fullstack, devops, civil, sipil, ui/ux, seo, copywriter, content creator, fresh graduate, intern, magang.

Aturan Delimiter Stripping: Jika baris header berformat gabungan seperti "Rifqi Setiawan | Backend Developer" atau "Budi Santoso - Civil Engineer", pecah berdasarkan delimiter (|, -, /, ,, •) dan buang segmen yang cocok dengan kamus jabatan. Jika seluruh string adalah jabatan murni (misal "FULLSTACK DEVELOPER"), tolak string tersebut sepenuhnya dan paksa pencarian ke baris berikutnya atau ke Orthogonal Anchors.

Pola 2 Guardrail — Institutional & Academic Header Blocklist:

Tolak mutlak kandidat nama yang mengandung token institusi pendidikan atau badan usaha: universitas, institut, sekolah tinggi, politeknik, akademi, stmik, stie, stkip, sma, smk, fakultas, jurusan, program studi, prodi, yayasan, kementerian, pt., cv., tbk.

Pola 3 Guardrail — Section & Meta-Header Blocklist:

Tolak mutlak frasa judul seksi: tentang saya, about me, curriculum vitae, resume, daftar riwayat hidup, biodata, data pribadi, personal information, profil, profile, ringkasan, summary, portofolio, portfolio.

Pola 4 Guardrail — Narrative Opening & Sentence Filter:

Nama orang tidak mengandung kata kerja, kata sifat deskriptif, atau konjungsi kalimat, serta memiliki panjang wajar 1 hingga 6 kata.

import re
from datetime import datetime
from typing import List, Tuple, Optional

INDONESIAN_MONTH_MAP = {
    "jan": 1, "januari": 1, "january": 1,
    "feb": 2, "peb": 2, "februari": 2, "pebruari": 2, "february": 2,
    "mar": 3, "mrt": 3, "maret": 3, "march": 3,
    "apr": 4, "april": 4,
    "mei": 5, "may": 5,
    "jun": 6, "juni": 6, "june": 6,
    "jul": 7, "juli": 7, "july": 7,
    "agu": 8, "ags": 8, "agst": 8, "agust": 8, "agustus": 8, "aug": 8, "august": 8,
    "sep": 9, "sept": 9, "september": 9,
    "okt": 10, "oct": 10, "oktober": 10, "october": 10,
    "nov": 11, "nop": 11, "november": 11, "nopember": 11,
    "des": 12, "dec": 12, "desember": 12, "december": 12,
}

CURRENT_PATTERNS = re.compile(
    r"(?i)\b(sekarang|saat\s*ini|kini|present|current|now|ongoing|masih\s*bekerja|aktif)\b"
)

def parse_indonesian_date_to_ym(
    raw_str: str, reference_ym: Tuple[int, int] = (2026, 10)
) -> Tuple[Optional[Tuple[int, int]], bool]:
    """
    Mengonversi string tanggal tidak terstruktur (misal: 'Agu 2022', 'Mei \'21', '03/2020', 'Sekarang')
    menjadi tuple (Year, Month) dan flag is_current.
    """
    if not raw_str or not raw_str.strip():
        return None, False

    s = raw_str.strip().lower()
    if CURRENT_PATTERNS.search(s):
        return reference_ym, True

    # 1. Cek format YYYY-MM atau MM/YYYY atau MM-YYYY
    m_iso = re.search(r"\b(19\d{2}|20\d{2})[\-\/\.](\d{1,2})\b", s)
    if m_iso:
        year, month = int(m_iso.group(1)), int(m_iso.group(2))
        if 1 <= month <= 12:
            return (year, month), False

    m_rev = re.search(r"\b(\d{1,2})[\-\/\.](19\d{2}|20\d{2})\b", s)
    if m_rev:
        month, year = int(m_rev.group(1)), int(m_rev.group(2))
        if 1 <= month <= 12:
            return (year, month), False

    # 2. Cek format Nama Bulan + Tahun (termasuk tanpa spasi 'Jul2022' atau tahun 2 digit "Mei '21")
    m_named = re.search(r"([a-z]{3,9})\.?\s*[\'\-\/]?\s*(\d{2,4})", s)
    if m_named:
        month_token = m_named.group(1)
        year_token = m_named.group(2)
        month_num = INDONESIAN_MONTH_MAP.get(month_token) or INDONESIAN_MONTH_MAP.get(month_token[:3])
        if month_num:
            year_num = int(year_token)
            if year_num < 100:
                year_num += 2000 if year_num < 50 else 1900
            if 1970 <= year_num <= 2030:
                return (year_num, month_num), False

    # 3. Fallback: Hanya Tahun (YYYY)
    m_year = re.search(r"\b(19\d{2}|20\d{2})\b", s)
    if m_year:
        return (int(m_year.group(1)), 6), False  # Default pertengahan tahun konservatif

    return None, False


def calculate_merged_experience_months(
    intervals: List[Tuple[Tuple[int, int], Tuple[int, int]]]
) -> int:
    """
    Menghitung durasi pengalaman kerja bersih (dalam bulan) menggunakan Calendar Interval Union
    agar pekerjaan yang tumpang tindih (overlap) tidak dihitung ganda.
    """
    if not intervals:
        return 0

    month_ranges = []
    for (sy, sm), (ey, em) in intervals:
        start_idx = sy * 12 + sm
        end_idx = ey * 12 + em
        if end_idx >= start_idx:
            month_ranges.append((start_idx, end_idx))

    if not month_ranges:
        return 0

    month_ranges.sort(key=lambda x: x[0])
    merged = [month_ranges[0]]

    for current_start, current_end in month_ranges[1:]:
        prev_start, prev_end = merged[-1]
        if current_start <= prev_end:
            merged[-1] = (prev_start, max(prev_end, current_end))
        else:
            merged.append((current_start, current_end))

    return sum((end - start + 1) for start, end in merged)
